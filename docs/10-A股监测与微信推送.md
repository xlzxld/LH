# 第 10 章 · A 股监测机器人：信号推微信，人工手动下单

> **学习目标**：搭一套"机器人盯盘 → 微信推送信号 → 你手动下单"的 A 股半自动体系。
> **配套代码**：`code/common/notify.py`（推送）、`code/ch08_monitor/monitor_astock.py`（监测）
> **耗时**：半天配置 + 长期运行
>
> **为什么 A 股是"推送 + 手动"而不是自动下单？**
> ① 个人程序直连券商下单需要专门通道（QMT/MiniQMT 等，有资金和开通门槛）；
> ② 新手阶段"信号 → 人工复核 → 手动下单"强制你确认每一笔，是最好的风控。
> 等策略经过几个月信号质量验证、你也熟练了，再研究自动化通道（第 13 章指引）。
>
> 🚨 **先想清楚再跟单**：本章监测规则里的双均线在 A 股宽基上长期跑不赢买入持有
> （第 4 章的诚实结果）。这套系统的价值是**执行基础设施 + 盯盘自动化**——请装进
> 你自己验证过的策略参数，而不是默认金叉就买。

## 10.2 开通微信推送（三选一，5 分钟）

| 渠道 | 免费额度 | 特点 | 适合 |
|------|---------|------|------|
| Server酱 | ~5 条/天 | 最简单，5 分钟搞定 | 信号不频繁的日线策略 |
| PushPlus | 较宽松 | 也简单 | 个人学习 |
| **企业微信群机器人** | **无限制** | 最稳定、支持群里多人收 | **长期运行（推荐）** |

**Server酱**：[sct.ftqq.com](https://sct.ftqq.com) 微信扫码 → 复制 SendKey → `.env` 填
`SERVERCHAN_SENDKEY=SCTxxx`，关注页面提示的接收公众号。

**PushPlus**：[pushplus.plus](https://www.pushplus.plus) 微信扫码 → 复制 token →
`.env` 填 `PUSHPLUS_TOKEN=xxx`。

**企业微信机器人**（免费且无条数限制）：
1. 微信里随便拉 3 个人建群（或企业微信 App 建群），拉不进人可用"自己的企业微信"建群
2. 群设置 → 群机器人 → 添加 → 复制 Webhook 地址
3. `.env` 填 `WECOM_WEBHOOK=https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx`

最后统一改渠道开关并测试：

```
NOTIFY_CHANNEL=wecom        # serverchan / pushplus / wecom
```

## 10.3 监测规则与配置

`.env` 里配置监测对象和参数（全部有默认值，可只改 WATCHLIST）：

```
WATCHLIST=etf:510300,etf:512100,etf:510500,stock:600519
MA_FAST=20
MA_SLOW=60
BREAKOUT_DAYS=60      # 创 60 日新高提醒
DRAWDOWN_PCT=10       # 距 60 日高点回撤超 10% 提醒
DRAWDOWN_DAYS=60      # 回撤参照窗口（"60日高点"的 60 可改）
LOOKBACK_START=20240101
```

三条内置规则（`check_signals` 函数，每条都带"去重键"，同一天同一信号只推一次）：

1. **均线金叉/死叉**：状态机——只在状态翻转当天发"买入参考/卖出参考"
2. **创 N 日新高**：突破提醒（海龟式入场点）
3. **回撤提醒**：从近期高点跌超阈值 → 风险警报

加自己的规则 = 在 `check_signals()` 里照葫芦画瓢加一段（比如 RSI 超买、放量突破），
消息格式完全复用。

## 10.4 三种运行姿势

```bash
# A. 检查一次，只在【有新信号】时才推送 —— 给定时任务用（推荐主用法）
python code/ch08_monitor/monitor_astock.py --once

# B. 强制推完整晨报（不看去重，每天 8:30 排一份，兼当"机器人活着"的心跳）
python code/ch08_monitor/monitor_astock.py --once --force

# C. 常驻循环，只在交易时段(9:35-11:30, 13:00-15:05)检查，其余时间休眠
python code/ch08_monitor/monitor_astock.py --loop --interval 300
```

推送纪律（免费渠道的配额很珍贵）：

- **无新信号不推送**——"安静 = 一切正常"，晨报（--force）才是心跳
- 同类事件提醒（新高/回撤）带 `ALERT_COOLDOWN_DAYS=3` 冷却，持续回撤期不会天天轰炸
- 推送**成功**才记录去重状态：微信接口偶发失败时信号不丢，下一轮自动重发
- `--codes 'etf:510300,stock:600519'` 可临时覆盖监测列表，不用改 .env

消息示例（微信里收到的样子）：

```

- 🔔 沪深300ETF(510300) [买入参考] 均线金叉：MA20 上穿 MA60，趋势转多
```

## 10.5 收到信号后：手动下单的标准动作

1. **先看盘面**：打开行情软件确认信号（均线、量能、大盘环境）——机器人给的是"候选"，你是"审批人"
2. **对照风控章程**（第 8 章动手环节写的那张纸）：仓位算法算出来该买多少？
3. **券商 App 下单**：ETF 用限价单挂在盘口附近，避免市价单冲击
4. **记录**：金额、理由、止损位写进你的交易日志（Excel/笔记都行）——日后复盘的原料

## 10.6 信号质量验证：先空跑一个月

**强烈建议：机器人先跑 1 个月，只记录不下单**，用第 5 章的方法统计：
信号数、如果照做会赚多少/亏多少、与回测预期是否一致。这份"前向验证"记录
是你决定真金白银的依据，也是从"监测"升级到"自动下单"的准入考试。

## 10.7 从"手动"到"自动"的路线图（远期）

1. QMT/MiniQMT（多数券商提供，通常 5 万~50 万资金门槛）——Python 直连下单
2. easytrader 等开源项目（模拟键鼠操作券商客户端，稳定性一般，自担风险）
3. 券商/聚宽的 PTrade 等托管平台

无论哪条路，都先把"人工审批"跑成纪律，再谈自动化。

## 动手环节

1. 开通任一推送渠道，收到测试消息。
2. 把 WATCHLIST 改成你真正想盯的 3~5 个标的，跑 `--once --force`
   （临时试一两个标的可用 `--codes 'etf:510300'` 不用改配置）。
3. 把 `MA_FAST/MA_SLOW` 改成你回测里最稳健的参数（第 5 章），保持监测与回测一致。
4. 进阶：给 `check_signals()` 加一条"放量"规则：成交量 > 5 日均量 2 倍时提醒。

## 常见的坑

- 推送收不到：检查渠道 key 是否复制全；Server酱超额（免费 5 条/天）；网络代理干扰。
- 周末运行显示金叉：用的是最近交易日数据，正常；定时任务请只排工作日。
- **推送内容对渠道方可见**：信号/心跳经过 Server酱、PushPlus 或企业微信的服务器中转，这些服务方技术上能看到消息文本（含标的与持仓数量）。介意的话优先用企业微信自建渠道，或精简推送内容。
- 盘中信号的"闪变"问题已由代码解决：盘中一律用**已收盘**的K线算信号
  （15:05 后才纳入当日 bar），你收到的金叉/死叉不会在收盘前"消失"。
  代价是信号比盘中看盘软件慢半根K线——这是消除假信号的合理代价。
- **时区**：交易时段按机器本地时间判断，机器必须设为北京时间。
  Windows 桌面一般没问题；海外 VPS 先 `timedatectl set-timezone Asia/Shanghai`（第 12 章）。
- 免费接口限流：已内置重试+缓存+1 秒间隔；缓存兜底时推送会标注"数据截至某日"，
  看到标注就知道数据不是最新的。
