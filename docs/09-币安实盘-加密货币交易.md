## 9.1 模式体系：机器人"会做什么"由什么决定

机器人的行为由 `resolve_mode()` 一个纯函数决定（有 8 组矩阵测试护体）：

| 你的输入 | 机器人实际行为 | 微信/日志显示 |
|---------|--------------|--------------|
| 不加 `--live` | 只算信号，一张单都不发 | DRY-RUN |
| `--live` + 测试网实例 | **真实下单**（假钱） | TESTNET |
| `--live` + 真账户，没加 `--real` | **拒绝下单**（防手滑） | LIVE-未确认 |
| `--live --real` + 输入确认短语 | 真实下单（真钱） | REAL |

关键设计：**下单开关以交易所实例的真实沙箱态为准**（`exchange.sandbox`），绝不信任
.env 配置旗标——历史上真实发生过"横幅写 TESTNET、实际连主网"的事故类别。
真钱模式还需要你在命令行**手动输入确认短语** `I-ACCEPT-FULL-LEGAL-RESPONSIBILITY`
（技术门禁替代人性自觉，见 9.6）。

## 9.2 合规与现实风险（大陆读者必读，读不懂就先只玩测试网）

在把真钱放进任何境外交易所之前，你需要知道这些**不是吓唬人的套话**：

1. **监管现状**：2021 年人民银行等十部门《关于进一步防范和处置虚拟货币交易炒作风险的通知》
   将境外交易所向境内居民提供服务定性为非法金融活动；币安服务条款也将中国大陆列为
   不服务地区。个人持有/交易的法律边界与实践执法力度持续变化，**你需要自行了解并
   承担全部合规责任**——本项目的真钱模式要求输入确认短语，就是这个意思。
2. **冻卡风险（最常见的现实伤害）**：用人民币场外购入 USDT（OTC）时，收款账户可能
   收到涉诈资金，导致银行卡/微信/支付宝被冻结数月，甚至被卷入调查。这是大陆用户
   真实发生频率最高的损失形态，损失的不是币，是"用钱的自由"。
3. **无消费者保护**：交易所跑路、被盗、风控误冻，你没有任何追索渠道。
4. **本项目的立场**：技术上教你完整机制（含真钱档），但**强烈建议**大多数人把
   测试网当作终点——它已经能练习全部工程能力；真钱档留给"已读完整合规背景、
   所在司法辖区允许、且资金亏完不影响生活"的读者。

## 9.3 机器人怎么工作（`live_bot.py` 逐段讲解）

主循环（简化版）：

```python
while True:
    try:
        run_once(...)        # 拉数据→算信号→调仓
    except Exception as exc:
        log.error(f"本轮失败，下轮重试: {exc}")   # 网络抖动不致死
    time.sleep(poll)         # 休眠到下一轮

def run_once(...):
    df = fetch_crypto_ohlcv(...)            # 最新 70 根 1h K线
    target = dual_ma_weights(df, 20, 60).iloc[-1]   # 0 或 1
    holding = get_holding(exchange, symbol)  # 问交易所：我现在有多少 BTC？
    if 目标满仓 and 实际空仓: 市价买入 quote_per_trade USDT
    if 目标空仓 and 实际持仓: 市价卖出全部
```

五个关键设计决策（都是实盘血泪，也是 Eng 评审后修订过的版本）：

1. **机器人只动自己的账本份额**：`data/state/live_bot_state.json` 记录机器人自己
   买入的数量（用"下单前后可用余额差值"记账，自动消化部分成交和基础币手续费）。
   卖出只卖自己买的——**绝不清算你手动买入的币**。所以给机器人一个独立子账户
   仍然是最干净的实践（账户里出现远超账本的币时机器人会告警一次）。
2. **信号只用已收盘的K线**：最新一根K线还没走完，均线值会随价格跳动，拿它算金叉
   会在盘中反复翻转（churn）。机器人每轮剔除最后一根未收盘K线；信号为 NaN
   （数据不足）时本轮"维持现状"，绝不反向交易。
3. **状态一致才不动**：目标仓位 == 机器人账本仓位就跳过，天然幂等（重复执行无副作用）。
4. **错误分诊**：网络抖动/限流等瞬时错误 → 记日志下一轮重试；鉴权失败/订单被拒等
   永久错误 → 微信推送 + 停机（重试没有意义，安静地循环报错才是最危险的静默失败）。
5. **日志双写 + 每日心跳**：控制台 + `data/live_bot.log`；每天第一条日志后向微信发
   一条心跳——**连续两天没收到心跳 = 机器人挂了**，推送通道本身就是报警器。

## 9.7 从双均线到你的策略

机器人只依赖一个函数 `dual_ma_weights(df, fast, slow) → 0~1`。
换策略 = 写一个同样签名的函数，比如：

```python
def breakout_weights(df, n=20, **_):
    """创 n 日新高满仓，跌破 n 日低点空仓（唐奇安通道，海龟法则的芯）"""
    hi = df["high"].rolling(n).max().shift(1)
    lo = df["low"].rolling(n).min().shift(1)
    w = pd.Series(float("nan"), index=df.index)
    w[df["close"] > hi] = 1.0
    w[df["close"] < lo] = 0.0
    return w
```

### 9.7.1 想控制仓位大小？分数目标已打通

`strategy.py` 提供了 `dual_ma_weights_sized(df, fast, slow, fraction)`——金叉时目标
仓位是 `fraction`（如 0.3 = 只投 30% 预算）而不是满仓。回测引擎与实盘机器人都支持
非 0/1 的分数目标：

- **回测**：直接把该函数的输出传给 `run_backtest`，锁仓/止损语义对分数目标同样生效。
- **实盘**：机器人把"目标>0"视为持有态，买入金额 = 每笔预算 × fraction；目标=0 清仓。
  一个工程简化要如实告诉你：**已持仓期间调整 fraction 不会触发调仓**（想改比例先手动卖出）。

⚠️ **任何新策略必须先回测（第 4~5 章流程）→ 再 dry-run → 再测试网**，一步不能少。

## 9.9 实盘后：评估、迭代与何时下线

上线不是终点，而是另一种开始。实盘最值钱的部分，是它暴露出的**回测和现实的差距**。

### 9.9.1 实盘 vs 回测，差距从哪来

跑满一个月后，把实盘结果和回测放一起对比。差距通常来自：

- **滑点与手续费比回测假设更大**：回测用的滑点/费率是估计值，实盘才是真实值。
- **信号延迟**：回测假设"收盘信号、次日开盘成交"，实盘有轮询间隔 + 网络延迟。
- **测试网 ≠ 主网**：测试网是独立撮合，行情和流动性都和主网不同（见常见坑）。
- **市场环境变了**：回测覆盖的是"过去"，实盘面对的是"现在"，两者可能已是不同市场。

**差距大 ≠ 你写错了**，但必须搞清楚差距来自"执行摩擦"（可优化）还是"策略失效"（该停）。

### 9.9.2 何时调参，何时放弃

| 现象 | 判断 | 动作 |
|------|------|------|
| 实盘略差于回测，但方向一致 | 正常（执行摩擦） | 继续观察，不动参数 |
| 实盘大幅跑输回测，且回撤超预设 | 可能过拟合或环境变了 | 停机复盘，先别急着调参 |
| 连续 N 笔亏损（N 上线前定） | 策略可能已失效 | 停机，重新走第 6~7 章验证流程 |

**最重要的纪律**：不要因为几笔亏损就当场改参数。实盘中"临时改参数"是最常见的自杀式操作——那等于在没有样本外验证的情况下裸奔。

### 9.9.3 止损：给实盘加上安全带

回测引擎早就有止损（`--stop-loss`），但**实盘机器人此前一直没有**——这是"回测带止损、实盘裸奔"的隐患。现在补齐了：

```bash
python code/ch07_binance/live_bot.py --live --stop-loss 0.05   # 持仓均价亏 5% 强制卖出
```

机器人每轮轮询都会检查：当前价是否跌破"持仓均价 × (1 - 止损比例)"，一旦击穿就**优先于任何信号**市价卖出，随后进入锁仓状态，等下一次新的金叉跳变才重新入场。止损卖单不受碎单过滤限制——认错单必须执行。

> 止损不是"防止亏钱"，而是"把单次亏损控制在你承受范围内"。真正的防亏靠第 8 章的仓位纪律 + 这里的止损，两者缺一不可。

### 9.9.4 下线标准：上线前就写好的"停车线"

**每一个上线的策略，都要在上线之前就写清楚"什么时候把它关掉"。** 不要等到亏了才临时讨论"要不要再等等"——那通常是亏更多的同义词。四条常见下线标准：

1. **回撤触发**：实际回撤超过预设上限（比如 20%），无条件停机。
2. **收益长期低于预期**：连续 N 周收益显著跑输回测基准（比如不到回测年化的一半）。
3. **逻辑失效**：策略赖以存在的市场逻辑消失了（比如"趋势市场"变成了"长期横盘震荡"）。
4. **规模超限**：资金规模超过了策略能容纳的上限（流动性不足、滑点失控）。

把这四条写下来、贴墙上，并在停机条件满足时**无条件执行**——这就是"没有圣杯"的落地方式：关键不是找永不失效的策略，而是建立一套能及时识别失效、果断下线的机制。

## 常见的坑

- `RequestTimeout` 频繁：轮询间隔别低于 30s；公共行情已走大陆可达域名，私有接口需网络条件。
- 下单报 `MIN_NOTIONAL`：金额低于交易所最小下单额（币安现货多数交易对 5~10 USDT）。
- 报 `Timestamp for this request...`：本机时间不准，Windows 设置里同步 Internet 时间。
- **测试网数据与真实行情不同**（测试网是独立撮合），策略表现只参考机制，不参考收益。
