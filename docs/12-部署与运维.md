# 第 12 章 · 部署与运维：让机器人 7×24 替你打工

> **学习目标**：把监测/交易机器人搬到"永不关机"的环境，配好定时任务、日志与崩溃自愈。
> **配套文件**：`scripts/scheduler_examples.txt`、`scripts/Dockerfile`、`scripts/docker-compose.yml`
> **耗时**：半天（VPS 路线）/ 1 小时（家里电脑路线）

## 12.1 运行环境的三档选择

| 方案 | 成本 | 适合 | 要点 |
|------|------|------|------|
| 家里电脑 | 0 | 起步期 | 关掉睡眠；Windows 任务计划定时跑 `--once` |
| NAS/树莓派 | 一次性硬件 | 长期监测 | 24h 低功耗；装 Linux + cron |
| 云服务器 VPS | ~30-60 元/月 | 币安实盘机器 | 优先选港澳/海外节点（网络问题少）；`restart: always` |

币安实盘机器人必须 VPS（7×24 + 网络稳定）；A 股监测机器人只需每天收盘后跑一次，
家里电脑 + 任务计划就够。

## 12.2 方案A：Windows 任务计划（最简单）

每天 15:10 收盘后自动推送 A 股信号（管理员 PowerShell 执行一次）：

```powershell
# 把 <项目根目录> 换成你的实际路径（不知道在哪？在项目目录运行 `pwd` 可查看）
schtasks /Create /TN "A股监测" /SC DAILY /ST 15:10 /TR ^
  "<项目根目录>\.venv\Scripts\python.exe <项目根目录>\code\ch08_monitor\monitor_astock.py --once"
```

```powershell
schtasks /Run /TN "A股监测"      # 立即试跑一次
schtasks /Delete /TN "A股监测" /F # 不要了就删
```

注意：任务计划运行时**没有你的终端环境**，所以路径必须写绝对路径、
`.env` 用绝对位置加载（本项目 `config.py` 按代码位置定位，天然支持）。

## 12.3 方案B：Linux VPS 完整部署（以 Ubuntu 为例）

```bash
# 1. 基础环境
sudo apt update && sudo apt install -y python3-venv git
sudo timedatectl set-timezone Asia/Shanghai     # 时区！A股时段判断依赖它

# 2. 上传代码（git 或 scp 二选一）
git clone <你的仓库> /opt/quant        # 记得 .gitignore 已排除 .env 和 data/
cd /opt/quant
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# 3. 配置
cp .env.example .env && nano .env      # 填密钥

# 4. cron 定时（crontab -e 添加；示例文件 scripts/scheduler_examples.txt）
10 15 * * 1-5 cd /opt/quant && ./.venv/bin/python code/ch08_monitor/monitor_astock.py --once >> data/monitor.log 2>&1
```

### 常驻进程用 systemd（币安机器人这样挂）

`/etc/systemd/system/binance-bot.service`：

```ini
[Unit]
Description=Binance dual-MA bot
After=network-online.target

[Service]
WorkingDirectory=/opt/quant
ExecStart=/opt/quant/.venv/bin/python code/ch07_binance/live_bot.py --live
Restart=always
RestartSec=30
Environment=TZ=Asia/Shanghai
Environment=PYTHONUTF8=1

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now binance-bot    # 开机自启 + 立即启动
systemctl status binance-bot               # 查看状态
journalctl -u binance-bot -f               # 实时日志
```

`Restart=always` 是核心：**进程崩了 30 秒后自动爬起来**，
配合机器人"以交易所余额为准"的无状态设计，断电断网都能自愈。

## 12.4 方案C：Docker（环境不一致恐惧症患者）

```bash
cd scripts
docker compose up -d --build      # 构建并后台启动监测机器人
docker compose logs -f            # 看日志
docker compose down               # 停止
```

`docker-compose.yml` 已配好：时区上海、`.env` 注入、`data/` 挂载持久化、
`restart: unless-stopped`。换机器部署 = 拷代码 + 拷 .env + 一条命令。

## 12.5 日志与监控：机器人也有"心电图"

三层防线（本项目已内建两层）：

1. **日志落盘**：`data/live_bot.log`、cron 重定向的 `data/monitor.log`——出事后回放时间线
2. **微信心跳**：让机器人每天固定时间发一条"我还活着"（第 9 章动手环节）。
   **连续两天没收到 = 立刻上服务器查看**——推送通道本身就是报警器
3. **外部监控**（可选进阶）：UptimeRobot 监控一个健康检查 URL，或 crontab 里加
   `curl -fs https://httpbin.org/get || 通知` 检测出口网络

## 12.6 故障演练（上线前必做）

人为制造事故，验证自愈：

- [ ] `kill` 进程 → systemd 30 秒内拉起，仓位判断无错乱
- [ ] 断网 10 分钟 → 恢复后日志出现重试成功的记录
- [ ] 服务器重启 → 服务自动恢复
- [ ] 手动在交易所撤单/反向操作 → 机器人下一轮自我纠正

## 12.7 安全加固清单（VPS）

- SSH 密钥登录、禁密码；`ufw` 只开 22/必要端口
- `.env` 权限 `chmod 600`；**绝不**提交到 git（本仓库 .gitignore 已挡）
- API Key 绑 IP 白名单（VPS 的固定 IP）
- 定期 `apt update && apt upgrade`

## 动手环节

1. 本机配好 Windows 任务计划或 Linux cron，连续 3 天自动收到推送。
2. 完成 12.6 的故障演练清单并记录恢复时间。
3. 给监测机器人加"心跳"：cron 每天 20:00 跑 `--once --force` 晨报式推送。
4. （进阶）Docker 路线完整部署一次。

## 常见的坑

- 服务器时区是 UTC → 监测在错误时间运行；`timedatectl` 先改上海。
- cron 环境变量与你终端不同 → python 路径用绝对路径、脚本内不依赖 shell 别名。
- 日志把磁盘写爆 → logrotate 或 cron 里定期清理（日志已按需追加，量不大）。
- Docker 里中文乱码 → 已设 `PYTHONUTF8=1`；自定义镜像时别漏。
